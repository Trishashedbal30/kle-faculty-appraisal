# Synthetic three-faculty presentation

The presentation sandbox is isolated at `runtime-demo/app.db` and serves at `http://127.0.0.1:8001`. The main application on port 8000 uses a different database and is not changed by these demo commands.

## Provision or run the sandbox

From the `kle-faculty-appraisal` project directory in PowerShell:

```powershell
.\.venv\Scripts\python.exe manage.py demo-provision
```

Set `KLE_DEMO_PASSWORD` in the local process environment before either command; use the same private value used when the sandbox was initialized. The application does not load `.env` automatically or write credentials to a file.

This command safely provisions River and Priya into an existing sandbox and can be rerun. It does not initialize, reset, overwrite, or delete Alex's existing report. If the demo server is already listening on port 8001, the new profiles and records are available immediately; no restart is required.

To start the sandbox when it is stopped:

```powershell
.\.venv\Scripts\python.exe manage.py demo --port 8001
```

This rechecks provisioning before serving. It uses only `runtime-demo/app.db`, not the port-8000 database.

## Demo logins

All demo accounts use the locally configured `KLE_DEMO_PASSWORD` value:

| Faculty | Username | Faculty profile |
|---|---|---|
| Alex Demo | `demo-faculty` | `demo-alex` |
| River Demo | `demo-river` | `demo-river` |
| Priya Demo | `demo-priya` | `demo-priya` |

Reviewer accounts use that same local value: `demo-hod`, `demo-dean`, and `demo-iqac`. The existing River account was renamed from `demo-other` to `demo-river`; its password is aligned with the locally configured value during provisioning. The other test account is not needed for this presentation.

Alex's active, completed v1 release is preserved. River and Priya receive three staged synthetic activity records each (research/conference, teaching/aggregate feedback, institutional service/committee), source documents, and correctly linked faculty accounts. Their consent is not pre-granted and evidence is not pre-verified: faculty consent and named reviewer evidence decisions must be recorded through the UI. No review or appraisal approval is generated by provisioning.

## Browser steps for each faculty report

For River, then repeat for Priya:

1. Sign in as `demo-river` or `demo-priya`, using the locally configured `KLE_DEMO_PASSWORD` value.
2. Open **Source records**. Grant consent separately for the faculty member's research, teaching, and administrative synthetic sources. The records are synthetic; no real person or institutional evidence is represented.
3. Open **Activities & evidence** and inspect the three staged records. To demonstrate faculty submission as well, use **Add activity**, upload/select a supporting synthetic file, and submit an activity whose category/kind matches an approved rule. For this added activity, grant source consent too.
4. Sign out and sign in as `demo-hod`. Open **Activities & evidence**, select River Demo or Priya Demo, and use **Review** on each of that faculty member's activities. Check the source file and locator, then choose **Verified** and enter a meaningful synthetic review note. Do not mark a record verified before review.
5. Sign out and return as the faculty user. Open **Appraisal workspace → Create appraisal plan**. Select the existing approved `SYNTHETIC training rubric`, describe completeness for research, teaching, and service, create the plan, inspect it, and lock it.
6. Use **Start appraisal run**. If the run is blocked, review its listed consent/evidence issues and correct them through the intended UI. Do not bypass the block.
7. Sign in as `demo-dean` and approve the quality-review stage after checking the report and evidence.
8. Sign in as `demo-hod` and endorse the appraisal.
9. Sign in as `demo-iqac` and approve final release. Publication only occurs after these three distinct human decisions.
10. Sign back in as the faculty user. Open **Reports & appeals** to inspect the released report and download its PDF. Each newly generated report is versioned for its faculty profile.

The synthetic policy is only a presentation/training rubric, not an institutional or UGC appraisal rule. The software records reviewer decisions; it does not approve policies, evidence, scores, or releases automatically.

## Demonstrate Alex's existing report

Sign in as `demo-faculty`, open **Reports & appeals**, inspect Alex Demo's existing released report, and download its PDF. Do not rerun or roll back Alex's report during this presentation unless you intentionally want to create a further version; River/Priya provisioning leaves Alex's report and active-release pointer unchanged.

## Test and rerun safety

Run the focused provisioning test and the project suite:

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests\test_demo.py
.\.venv\Scripts\python.exe -m pytest -q
```

`test_demo.py` verifies account bindings, all three activity categories, staged source files, no preapproved evidence or pregranted consent, no duplicate entities on rerun, and preservation of Alex's existing release.
